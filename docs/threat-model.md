# Threat model

STRIDE, following the [dbsc-toolkit threat model](https://github.com/SulimanAbdulrazzaq/dbsc-toolkit/blob/main/docs/security/threat-model.md) so the two can be compared line by line. Scope: the `dbsc()` Better Auth plugin and `@assistant-ui/better-auth-dbsc/core`.

Every mitigation below names the test that proves it. The tests run against Better Auth on SQLite with keys generated by `jose`, not against Chrome.

Registration and refresh both validate the public key. This includes keys returned by custom stores. Both require an RS256 modulus of at least 2048 significant bits in minimal unsigned encoding.
When an expected origin is configured, a present audience list must contain at least one URL and every entry must match that origin.

## Assets

- **The binding**: a `dbscSession` row tying a Better Auth session to the device's public key and its thumbprint.
- **Challenges**: `<issued ms>.<nonce>.<HMAC>` under the Better Auth secret, bound to a purpose (`register` or `refresh`) and to the session token. They are never stored.
- **The bound cookie**: `<expires>.<issued>.<nonce>.<HMAC>` over the session token. It lives 5 minutes, and only a proof from the device key renews it.
- **The store**: `dbscSession` by default, or anything implementing `DbscStore`.

## Threats

| ID | Threat | Here | How | Test |
|---|---|---|---|---|
| S1 | Stolen cookies replayed on another device | Mitigated | A bound session without a live bound cookie is treated as signed out: the session cookie is dropped from the request before any endpoint reads it. The bound cookie expires within `boundCookieMaxAge`, and only the device key renews it. | `treats a bound session without its bound cookie as signed out`, `refuses an expired bound cookie until the browser refreshes`, `refuses a bound cookie minted for another session` |
| S1 | Stolen cookies used inside the bound-cookie window | Mitigated on `freshProof` paths | Sensitive paths need a bound cookie that a device-signed refresh minted while the browser held that action's challenge: the cookie carries the challenge nonce under its MAC. A copied cookie, however fresh, never answers one, and no clocks are compared, so skew between instances can't make an old cookie look newer. A path in both `freshProof.paths` and `enforcement.exclude` is refused at startup. Other paths keep up to `boundCookieMaxAge` of exposure. | `makes a bound session prove itself again…`, `is not answered by a bound cookie from before the challenge`, `is not answered by a copied cookie minted on a server whose clock runs ahead`, `refuses a path that needs a fresh proof but is excluded from enforcement` |
| S1 | Captured registration proof replayed to renew a stolen session | Mitigated | A repeated registration from the same key gets the same answer, so a lost response can be fetched again, but its bound cookie expires `boundCookieMaxAge` after the challenge was issued, not after the replay. | `does not let a replayed registration outlive the first bound cookie` |
| S1 | Stolen session token sent as `Authorization: Bearer`, alone, next to the copied cookie, or next to the thief's own session cookie | Mitigated | The gate reads every session token in the request, with the bearer token read the way `bearer()` reads it. A request with a bearer token that carries a bound session is refused with 401 unless the bound cookie proves it and the cookie and bearer token name that same session. It refuses rather than dropping the cookie, because `bearer()` may rewrite the cookie header after the gate. Tested with `dbsc()` before and after `bearer()`. | `refuses a bound session sent as a bearer token`, `refuses a stolen cookie sent again as a bearer token`, `refuses a stolen bearer token next to the thief's own session cookie`, `refuses a stolen bearer token alone`, `refuses a bound browser that sends another session as a bearer token` |
| S1 | Copied `multiSession()` cookie of a bound session | Mitigated | Each `_multi-` cookie naming a bound session without a live bound cookie is dropped (or, with a bearer token, the request is refused), so it can't list, switch to, or revoke the owner's session. | `does not leak a bound session through a copied multiSession() cookie`, `refuses a copied multiSession() cookie sent with a bearer token` |
| S1 | Copied `admin_session` cookie of a bound admin, next to a copy of the impersonation session | Mitigated | `admin_session` naming a bound session without a live bound cookie is dropped, so `/admin/stop-impersonating` can't return or restore the admin's session. The impersonation session itself is a separate session and is bound only if the browser registers it. | `does not leak a bound admin session through a copied admin_session cookie`, `lets the bound admin stop impersonating` |
| S1 | Copied cookies read by `getCookieCache()` or `getSessionCookie()` in middleware | Not mitigated (documented) | These helpers decode cookies without calling Better Auth, so no plugin hook runs. The README says to use them for redirects only and to authorize with `auth.api.getSession`, which is gated, cookie cache included. | `does not answer from session.cookieCache for a copied cookie` |
| S2 | Attacker's key substituted at registration | Mitigated | The registration JWT must be self-signed by the key it carries. The registration challenge appears only in the sign-in response, is bound to that session token, and expires. A session binds once; another key is refused. | `refuses a challenge this server did not issue for this session`, `answers a repeated registration from the same key, and refuses another key` |
| T1 | Refresh proof replayed | Mitigated | `store.spend` is a guarded `incrementOne`: a challenge is spent once, and older ones are refused once a newer one is spent. Atomic across instances. | `spends a proof once even when requests race`, `refuses an older challenge once a newer one is spent` |
| T1 | A refresh challenge reused for registration, or the reverse | Mitigated | The purpose is inside the challenge MAC. | `does not take a refresh challenge for a registration` |
| T1b, T3, T4 | Per-request proof replay, DPoP | Not applicable | This plugin has no per-request proof header and no DPoP. Those belong to the toolkit's JS polyfill tier. | — |
| T2 | Stored keys changed by someone with database access | Out of scope | Access control on the database. Thumbprints make a swapped key visible. | — |
| R1 | Theft goes unnoticed | Mitigated | `onEvent` reports `proof_rejected` (a refresh signed by the wrong key, the strongest theft signal) and `credential_missing` (a bound session arriving without its bound cookie, by cookie, bearer token, `multiSession()` cookie, or `admin_session`). | `reports the lifecycle and theft signals without key material` |
| I1 | Keys or challenges leak into logs | Mitigated | Events carry session and user ids and reason codes only. The plugin logs no keys, challenges, cookies, or tokens. | `reports the lifecycle and theft signals without key material` |
| I2 | Key copied from the browser profile by malware | Mitigated for DBSC browsers | Native DBSC keeps the key in the TPM or Secure Enclave. There is no software-key tier here. For routes that must resist this, `freshProof` with `unbound: "deny"` refuses sessions that aren't bound. | `denies plain sessions on paths that need a device-bound session` |
| D1 | Challenge flood exhausts storage | Mitigated | Challenges are stateless: issuing one writes nothing. Register and refresh are also rate limited through Better Auth's limiter. That limiter is on in production by default and off in development. | `writes nothing when it hands out a challenge`, `limits register and refresh through Better Auth's limiter` |
| D1b | Bindings outlive their sessions in a custom store | Mitigated | `DbscStore.delete` runs from Better Auth's session delete hook on every way a session ends. Sessions that expire unseen are pruned with the sessions. | `releases a binding in a custom store when its session ends` |
| D2 | Replays or garbage lock the owner out | Mitigated | A challenge is spent only after the signature verifies, so garbage spends nothing. A copied cookie can't reach any endpoint that changes the session, sign-out included. | `does not let garbage proofs spend a challenge`, `never lets a copied cookie sign the owner out` |
| E1 | Algorithm confusion (`none`, HS256 with the public key) | Mitigated | Only ES256 and RS256 are accepted, checked before any key is imported. The key type must match the algorithm, private members are refused, and RSA keys must be at least 2048 bits. | `rejects alg: none`, `rejects HS256 signed with the public key as the secret`, `rejects an RSA key presented for ES256`, `rejects a private JWK`, `rejects RSA keys under 2048 bits` |
| E2 | A plain session treated as device-bound | Mitigated | `getDbscStatus` answers `bound` only for a session bound to a device key, proven by a live bound cookie. `unbound` sessions are labeled as such. | `binds the session and returns the session config`, `leaves sessions alone in browsers without DBSC` |

## Not covered

- **Malware running inside the browser** can ask the TPM to sign, so it can refresh like the real browser. DBSC stops cookies from being used elsewhere, not code running on the device.
- **Browsers without DBSC** get no binding. There is no JavaScript polyfill tier. Use `freshProof` with `unbound: "deny"` or `"fresh-session"` where that matters.
- **Unguarded paths inside the cookie window.** A thief who copies both cookies keeps access to paths outside `freshProof` until the bound cookie expires (5 minutes by default).
- **The origin check is skipped on `/dbsc/register` and `/dbsc/refresh`.** The browser sends those requests itself, and nothing promises they carry `Origin`. A page on another site can't set `Secure-Session-Response` or `Sec-Secure-Session-Id`, has no challenge to sign, and has no key. Refresh refuses any request without `Sec-Secure-Session-Id`.
- **Not tested against real Chrome.** The tests play the browser with `jose`.
